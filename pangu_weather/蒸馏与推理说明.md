# pruned_96 蒸馏与推理说明

本文档说明如何从组委会盘古模型得到固定的 `pgw_lite_pruned_96` 学生模型，生成最终推理检查点 `model_fp16_alias_compact.pth`，并运行推理。所有命令均在 `pangu_weather/` 目录执行。

## 1. 环境与输入

- 竞赛服务器已配置的 Python、PyTorch/DTK、Apex 和 OneScience 环境。
- ERA5 路径、训练/验证年份和批量在 `conf/config.yaml` 中配置。
- 组委会原始检查点放在 `data/checkpoints/model_bak.pth`。
- 以单卡 `cuda:0` 运行，并预留足够的检查点存储空间。

## 2. 生成 pruned_96 初始化

先转为 FP16，再对通道和注意力头做结构化剪枝。学生结构固定为 patch `[2,8,8]`、宽度 `96`、head `[3,6,6,3]`、深度 `[2,6,6,2]`。

```bash
python scripts/convert_fp16.py \
  --source data/checkpoints/model_bak.pth \
  --output data/checkpoints/model_teacher_fp16.pth

python scripts/prune_structured.py \
  --source data/checkpoints/model_teacher_fp16.pth \
  --output data/checkpoints/model_pgw_lite_pruned_96.pth \
  --target-profile pgw_lite_pruned_96 \
  --dtype fp16
```

## 3. 知识蒸馏

`distill_train.py` 只支持上述 `pruned_96` 模型。损失为全 69 通道真值 L1、教师 L1 和 `layer1/layer2` 特征对齐损失的加权和，权重分别为 `0.3/0.5/0.2`。

```bash
python distill_train.py
```

训练自动断点续训，并输出：

- `data/checkpoints/model_pgw_lite_pruned_96_latest.pth`：最新可续训状态；
- `data/checkpoints/model_pgw_lite_pruned_96_train.pth`：最优验证状态；
- `data/checkpoints/model_pgw_lite_pruned_96_fp16.pth`：最优 FP16 推理权重。

## 4. 生成实际 FP16 alias-compact 检查点

先做别名保真的 FP16 转换，再无损删除 OneFuser 重复别名。
已评分的 `model_fp16_alias_compact.pth` 实际包含 31.8988 MiB FP16 和
2.5312 MiB INT64，没有 INT8 tensor；历史 `quantization` 元数据不能代替真实 dtype 审计。

```bash
python scripts/convert_fp16.py \
  --source data/checkpoints/model_pgw_lite_pruned_96_fp16.pth \
  --output data/checkpoints/model_pgw_lite_pruned_96_converted_fp16.pth

python scripts/compact_fuser_alias_checkpoint.py \
  --source data/checkpoints/model_pgw_lite_pruned_96_converted_fp16.pth \
  --output data/checkpoints/model_fp16_alias_compact.pth
```

如果输出文件已存在，转换脚本会拒绝覆盖；请先将旧实验产物移到独立归档目录。

可选的 Stage 1 index-elision 候选必须以上述文件为输入：

```bash
python scripts/elide_deterministic_indices.py \
  --source data/checkpoints/model_fp16_alias_compact.pth \
  --output data/checkpoints/model_fp16_index_elided.pth
```

## 5. 编译说明

Python 模型无需手工编译。首次推理时，`hip_earth_attention_tiled.py` 调用 `/opt/dtk/bin/hipcc` 将 `hip_kernels/earth_attention_tiled_fwd.hip` 编译为共享库，并按源码和编译选项指纹缓存到 `logs/hip_earth_attention_tiled_build/`。默认命令等价于：

```bash
/opt/dtk/bin/hipcc -O3 -std=c++17 -fPIC --shared \
  -DPANGU_FULL_ROW_SCORE_STRIDE=144 \
  -DPANGU_FULL_ROW_QK_TILE=16 \
  hip_kernels/earth_attention_tiled_fwd.hip \
  -Wl,-rpath,/opt/dtk/lib -o <fingerprint>.so
```

常规用户不必手工执行该命令；确保 `/opt/dtk/bin/hipcc` 可用且 `logs/` 可写即可。
`PANGU_P2_PREBUILD_HIP=1` 只是独立 A/B 候选，评分默认在通过加速门前保持关闭。

## 6. 推理与结果

直接指定最终检查点：

```bash
PANGU_CHECKPOINT=model_fp16_alias_compact.pth python inference.py
python result.py
```

运行 dense-mask 释放的独立 A/B 候选时，仅增加
`PANGU_P2_REGION_RELEASE=1`；该开关在完成 DCU 5×4 和平台审计前默认关闭。

正式模型 ZIP 要求根目录只有 `model_fp16.pth`，可这样制作：

```bash
mkdir -p /tmp/pangu_model
cp data/checkpoints/model_fp16_alias_compact.pth /tmp/pangu_model/model_fp16.pth
(cd /tmp/pangu_model && zip -9 ../model.zip model_fp16.pth)
```

推理输出位于 `result/output/`，`result.py` 生成 `result/rmse.npy` 和 `result/acc.npy`。代码提交包由以下命令生成并自动审计：

```bash
bash scripts/build_submission.sh
```

## 7. 核对要点

- 日志中模型 profile 应为 `pgw_lite_pruned_96`。
- 最终模型必须保留 `model_profile`、`distillation` 和 `alias_compaction` 来源元数据。
- 审计必须读取实际 tensor：当前基线应为 0 INT8，不得用历史元数据声称 62 个 INT8。
- index-elision 候选必须保留生成 index 的 key/shape/dtype/SHA manifest，且 69 通道输出逐字节一致。
- 提交前用 `scripts/audit_submission_package.py` 检查代码 ZIP 和模型 ZIP。
