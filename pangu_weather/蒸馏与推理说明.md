# pruned_96 蒸馏与推理说明

本文档说明如何从组委会盘古模型生成固定的 `pgw_lite_pruned_96` 学生模型，生成 67 个逻辑 Linear 全 FP16 + alias compaction 最终检查点 `model_fp16_alias_compact.pth`，并运行推理。所有命令均在 `pangu_weather/` 目录执行。

## 1. 环境与输入

- 竞赛服务器已配置的 Python、PyTorch/DTK、Apex 和 OneScience 环境。
- ERA5 路径、训练/验证年份和批量在 `conf/config.yaml` 中配置。
- 组委会原始检查点为 `pangu_backups/model_bak.pth`；如果已放入 `data/checkpoints/model_bak.pth`，相应替换下面的路径。
- 以单卡 `cuda:0` 运行，并预留足够的检查点存储空间。

## 2. 生成 pruned_96 初始化

先将官方 FP32 权重转为 FP16，再对通道和注意力头做结构化剪枝。学生结构固定为 patch `[2,8,8]`、宽度 `96`、head `[3,6,6,3]`、深度 `[2,6,6,2]`。剪枝脚本同时执行 patch4 到 patch8 的确定性 kernel/位置偏置迁移，并重建目标网格 buffer。

```bash
python scripts/convert_fp16.py \
  --source pangu_backups/model_bak.pth \
  --output data/checkpoints/model_teacher_fp16.pth

python scripts/prune_structured.py \
  --source data/checkpoints/model_teacher_fp16.pth \
  --output data/checkpoints/model_pgw_lite_pruned_96.pth \
  --target-profile pgw_lite_pruned_96 \
  --dtype fp16
```

生成后日志必须显示：

```text
Target patch_size: [2, 8, 8]
Target embed_dim: 96, num_heads: (3, 6, 6, 3)
Target depth blocks: [2, 6, 6, 2]
```

## 3. 知识蒸馏

`distill_train.py` 只支持上述 `pruned_96` 模型。损失为全 69 通道真值 L1 和教师输出 L1 的等权加权和，权重为 `0.5/0.5`；不使用中间特征 hint loss。

```bash
HDF5_USE_FILE_LOCKING=FALSE python distill_train.py
```

训练自动断点续训，并输出：

- `data/checkpoints/model_pgw_lite_pruned_96_latest.pth`：最新可续训状态；
- `data/checkpoints/model_pgw_lite_pruned_96_train.pth`：最优验证状态；
- `data/checkpoints/model_pgw_lite_pruned_96_fp16.pth`：最优 FP16 推理权重。

只验证工具链而不训练时，可在后续命令中用 `model_pgw_lite_pruned_96.pth` 代替 `model_pgw_lite_pruned_96_fp16.pth`。这种产物仅用于流程冒烟测试，不代表正式蒸馏模型精度。

## 4. 67 Linear 全 FP16 与 alias compaction

先做别名保真的 FP16 转换，再生成量化脚本所需的确定性敏感度清单。正式提交配置通过 `--keep-count 67` 保留全部 67 个逻辑 Linear 为 FP16，因此最终检查点不含 INT8 权重和 `_scale` tensor。最后删除 OneFuser 重复别名，并保留运行时最后写入的 `Fuser` 权重。敏感度结果在该配置下不影响层选择，仅作为当前量化脚本的输入契约保留。

```bash
python scripts/convert_fp16.py \
  --source data/checkpoints/model_pgw_lite_pruned_96_fp16.pth \
  --output data/checkpoints/model_pgw_lite_pruned_96_converted_fp16.pth

python scripts/analyze_quant_sensitivity.py \
  --checkpoint data/checkpoints/model_pgw_lite_pruned_96_converted_fp16.pth

PANGU_QUANTIZE_PROFILE=pgw_lite_pruned_96 \
python scripts/quantize_mixed_precision.py \
  --keep-count 67 \
  --checkpoint data/checkpoints/model_pgw_lite_pruned_96_converted_fp16.pth \
  --output data/checkpoints/model_pgw_lite_pruned_96_quantized.pth

python scripts/compact_fuser_alias_checkpoint.py \
  --source data/checkpoints/model_pgw_lite_pruned_96_quantized.pth \
  --output data/checkpoints/model_fp16_alias_compact.pth
```

敏感度扫描输出 `data/quant_sensitivity.json`。如果该文件或后续输出已存在，脚本会拒绝覆盖；请先移到独立归档目录。

压缩后必须审计真实 tensor，不得只读 `quantization` 元数据：

```bash
python - <<'PY'
import os
import torch

p = "data/checkpoints/model_fp16_alias_compact.pth"
c = torch.load(p, map_location="cpu", weights_only=False)
s = c["model_state_dict"]
int8 = [k for k, v in s.items() if torch.is_tensor(v) and v.dtype == torch.int8]
scales = [k for k in s if k.endswith("_scale")]

assert c["quantization"]["fp16_keep_count"] == 67
assert c["quantization"]["quantized_keys_count"] == 0
assert len(int8) == 0, len(int8)
assert len(scales) == 0, len(scales)
assert c["alias_compaction"]["alias_pair_count"] == 224
print("file size MiB:", round(os.path.getsize(p) / 1024**2, 2))
print("PASS: 67 Linear FP16 + alias compaction")
PY
```

## 5. 编译说明

Python 模型无需手工编译。首次推理时，`hip_earth_attention_tiled.py` 调用 `/opt/dtk/bin/hipcc` 将 `hip_kernels/earth_attention_tiled_fwd.hip` 编译为共享库，并按源码和编译选项指纹缓存到 `logs/hip_earth_attention_tiled_build/`。默认命令等价于：

```bash
/opt/dtk/bin/hipcc -O3 -std=c++17 -fPIC --shared \
  -DPANGU_FULL_ROW_SCORE_STRIDE=144 \
  -DPANGU_FULL_ROW_QK_TILE=16 \
  hip_kernels/earth_attention_tiled_fwd.hip \
  -Wl,-rpath,/opt/dtk/lib -o <fingerprint>.so
```

常规用户不必手工执行该命令；确保 `/opt/dtk/bin/hipcc` 可用且 `logs/` 可写即可。

## 6. 推理与结果

先显式指定最终检查点做 1 个 batch 的加载和前向冒烟测试：

```bash
HDF5_USE_FILE_LOCKING=FALSE \
PANGU_CHECKPOINT=model_fp16_alias_compact.pth \
PANGU_MAX_INFERENCE_BATCHES=1 \
python inference.py
```

日志应显示加载显式指定的权重，且 profile 为 `pgw_lite_pruned_96`。完整推理时去掉样本上限，并在全部输出生成后计算指标：

```bash
HDF5_USE_FILE_LOCKING=FALSE \
PANGU_CHECKPOINT=model_fp16_alias_compact.pth \
python inference.py

python result.py
```

推理输出位于 `result/output/`，`result.py` 生成 `result/rmse.npy` 和 `result/acc.npy`。不得将单 batch 冒烟测试与旧输出混合后运行 `result.py`。

正式模型 ZIP 要求根目录只有 `model_fp16.pth`：

```bash
mkdir -p /tmp/pangu_model
cp data/checkpoints/model_fp16_alias_compact.pth /tmp/pangu_model/model_fp16.pth
(cd /tmp/pangu_model && zip -9 ../model.zip model_fp16.pth)
```

代码提交包由以下命令生成并自动审计：

```bash
bash scripts/build_submission.sh
```

## 7. 核对要点

- 日志中模型 profile 应为 `pgw_lite_pruned_96`。
- 最终模型必须保留 `model_profile`、`quantization` 和 `alias_compaction` 元数据；`distillation` 为可选来源记录，存在时必须与实际蒸馏配置一致，不得为未训练权重伪造该字段。
- alias compaction 后必须不存在 INT8 tensor 和 `_scale` tensor，`fp16_keep_count` 必须为 67，`quantized_keys_count` 必须为 0，`alias_pair_count` 必须为 224。
- 审计必须读取实际 tensor，不得仅根据量化元数据判断最终存储形态。
- 提交前用 `scripts/audit_submission_package.py` 检查代码 ZIP 和模型 ZIP。
